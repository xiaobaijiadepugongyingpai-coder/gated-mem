# 项目备忘录：Agent 记忆插件（LSTM 门控语义方向）

> **状态**：调研完成，设计未定型，实验未开始
> **更新时间**：2026-11-10
> **一句话**：做带独立遗忘门的 agent 记忆插件——不训练 LSTM，用 LSTM 的**门控语义**做策略层。

---

## 一、项目定位

**不做什么**

- 不训练 LSTM / RNN 模型
- 不改基座模型、不做 test-time training
- 不追求"记住更多"，追求"该忘的忘掉"

**做什么**

用 LSTM 的三个门作为**设计范式**，映射成可实现的调度策略：

| LSTM 元件 | 插件中的对应物 |
|---|---|
| `h_t` 隐状态 | 短期记忆（近窗口） |
| `C_t` 细胞状态 | 长期记忆（持久化条目） |
| `i_t` 输入门 | 写入决策（这条要不要进库） |
| `f_t` 遗忘门 | 淘汰决策（这条该不该降权/删除） |
| `o_t` 输出门 | 召回决策（此刻该取回哪些） |

## 二、调研结论

### 2.1 有没有人做过：有，但没做成

| 层次 | 代表 | 对我们意味着什么 |
|---|---|---|
| **模型架构级** | [xLSTM](https://github.com/NX-AI/xlstm)（2215★）、[RMT](https://github.com/lucidrains/recurrent-memory-transformer-pytorch)（425★）、Titans（NeurIPS 2025） | 需重训基座，**不可用** |
| **系统架构级** | [agentic-lstm](https://github.com/AlexandreRL/agentic-lstm)（0★，2026-09）、LSTM-MAS（arXiv 2601.11913） | **最接近我们的想法**，证明技术上跑得通，但无社区验证 |
| **插件层** | claude-mem、Mem0、Zep、Letta、mazemaker | **没有一个用 LSTM**，全是 LLM 摘要 + 向量/图/文件 |

**关键判断**：想法不新，但没人把它做成可用的东西。`agentic-lstm` 的形态值得参考（`x_t → RECALL → REASON → ACT → CONSOLIDATE → FORGET`），自报省 79% prompt token，但它 0 星、benchmark 是自己脚本跑的。

### 2.2 LSTM 的演进：没被淘汰，是被吸收了

xLSTM、Mamba-2、Gated DeltaNet 现在可统一写成同一个式子：

```
C_t = f_t ⊙ C_{t-1} + i_t ⊙ (v_t k_tᵀ)
```

即"门控线性注意力"。**遗忘门成了整个领域的公共词汇表。**

2026 年 6 月 JKU Linz 的对比研究（arXiv 2606.12364）结论：
- xLSTM 在代码预训练 / 蒸馏 / 时序 / 合成状态追踪上综合最强
- 原因不是玄学，是**输入门与遗忘门独立**；Mamba-2 把两门绑在一根轴上（本质是 GRU），丧失"重新加权早期内容"的能力
- 但也承认：推理/常识上领先不到 0.1 分，"赢得很薄"

**JANET（2018）早已证明：只保留遗忘门也能工作。**

### 2.3 主流记忆插件的六个功能段

| # | 段 | 主流做法 | 共识度 |
|---|---|---|---|
| 1 | 捕获 Capture | `SessionStart` / `UserPromptSubmit` / `PostToolUse` / `Stop` | 高 |
| 2 | 提炼 Distill | LLM 摘要 / LLM 判 ADD-UPDATE-DELETE / 不提炼 | 中 |
| 3 | 存储 Store | SQLite+FTS5 / 向量库 / 图 / 纯 Markdown | 中 |
| 4 | 检索 Retrieve | 向量 / BM25 / 混合 / 图遍历 / 三层渐进 | 中 |
| 5 | 注入 Inject | 常驻 / 索引常驻+按需 / 每轮自动 / 模型自主 | 低（路线之争） |
| 6 | 维护 Maintain | 去重 / 冲突消解 / 后台合并 / 容量上限 / **衰减** | **最低** |

**规模参考（2026-10-31）**：claude-mem 105,687★ / Mem0 66,894★ / Supermemory 31,172★ / Graphiti 31,591★ / Letta 25,091★ / Basic Memory 4,123★

**信号**：claude-mem 星数已超 Mem0，说明"贴着工作流的宿主插件"传播势能强于"通用 API"。

### 2.4 空白区（这是我们要打的地方）

| 空白 | 现状 |
|---|---|
| **衰减 / 遗忘** | 九个主流插件**没有一个做真正的遗忘**，只有容量截断 |
| **时序优先级** | 除 Graphiti 外，普遍无法表达"第 40 轮覆盖了第 3 轮" |
| **写入质量校验** | 仅 dsh-shared-memory 等小众方案有 |
| **可观测性** | 几乎无法回答"为什么记了这条、为什么没记那条" |

> 注：**学术侧** 2026 年已有专门工作（FadeMem、WMT、TiMem、Mem-α），只是还没进主流插件。所以这是"插件生态的空白"，不是"研究的空白"——意味着有现成方法可借鉴。

## 三、设计主张（核心）

### 3.1 门控必须分离

**不能用一个 `importance` 分数同时管写入和淘汰。**

这是 xLSTM 赢 Mamba-2 的唯一结构性原因，同样适用于记忆策略：**写入强度和淘汰强度是两个独立旋钮**。

共用一个分数 ≈ 把自己的记忆系统做成 GRU。

### 3.2 写入与遗忘的不对称性

| | 写入 `i` | 遗忘 `f` |
|---|---|---|
| 信号在何时 | **当下就有**（新颖度、是否决策、用户是否强调） | **要等未来**（半年没用 = 真没用？还是没遇到场景？） |
| AI 能判断吗 | 能，信息现成 | 不能，只能猜 |
| 错了的代价 | 噪音 | **永久丢失** |

**结论**：

> 写入参数交给模型，遗忘参数交给使用反馈，衰减率交给记忆类型。

让 LLM 猜"这条将来有没有用"，它会系统性保守（全标高重要），最终退化成不遗忘。

### 3.3 衰减用幂律，不用指数

| 形式 | 问题 |
|---|---|
| 指数 `decay^hours`（0.995/h） | 跑 100+ 天后早期重要记忆掉进"指数悬崖"，突然归零 |
| 幂律 `score(0) × t^(-β)` | 前期慢、后期也慢，贴近艾宾浩斯曲线，早期关键记忆优雅衰减 |

**长周期场景必须用幂律。**

### 3.4 按类型分层衰减（零 AI 成本）

| 类型 | 衰减 | 理由 |
|---|---|---|
| 程序性（"这个项目用 pytest"） | 几乎不衰减 | 最值得复用 |
| 决策（"决定不用 Redis"） | 极慢 | 关闭了备选方案 |
| 用户偏好 | 极慢 | 稳定 |
| 临时观察 / 工具输出 | 一个会话内消散 | 高噪音 |

依据：FadeMem（arXiv 2601.18642）双层差分衰减，超过 Mem0 且**存储省 45%**。

### 3.5 反馈驱动参数更新（真正的"自动"）

用使用结果当标签，纯统计，不需训练：

| 信号 | 怎么取 | 更新 |
|---|---|---|
| 记忆被检索后**被引用** | 检查后续回复是否用到 | `half_life *= 1.1` |
| 被检索但**未被使用** | 同上 | `half_life *= 0.95` |
| 被用户**纠正** | 文本比对 / 显式反馈 | `half_life *= 0.5`，标 superseded |
| 检索后**任务成功** | 任务级信号 | 该批记忆集体加权 |

**Mem-α 用 RL 学的就是这个，手写 EMA 可先拿到 ~80% 收益。**

### 3.6 冲突检测的余弦区间

```
< 0.6   → 无关，正常写入
0.6–0.9 → 冲突高发区，必须显式处理（"用 PostgreSQL" vs "用 MySQL"）
> 0.9   → 近重复，去重
```

**大多数系统只做 >0.9 的去重，中间段被静默跳过——而这正是新旧事实打架的地方。**

## 四、实验方案

### 4.1 为什么不能用 LoCoMo / LongMemEval

| 数据集 | 缺陷 |
|---|---|
| LoCoMo | **94%** 的问题只需 ≤ 2 个 session |
| LongMemEval | **85%** 同理；最多只允许 **2 次**知识更新 |
| PersonaMem | 变化跨不超过 3 个 session |

**我们的遗忘机制在这些数据集上根本不会被触发。**

### 4.2 该用的三个

| Benchmark | 时间 | 规模 | 用途 |
|---|---|---|---|
| **StateMemBench** | 2026-08 | 234 个多会话场景 | **第一站**，小、快、closed-pool 评分 |
| **Memora**（ACL 2026 Findings） | 2026-07 放数据 | 10 persona × ~1991 session，avg **1171 次记忆操作**（63% 增 / 18% 改 / 19% 删） | 主战场 |
| **MemOps** | 2026-07 | 4 类操作 trace | 开发期诊断日志结构 |

**参考基线结果**（Memora quarterly）：即使最强系统也只有 20 多分/100；memory agent 掉得最狠——MemoBase remembering 43.6 → **15.2**，MemoryOS 51.8 → **25.1**。多步推理几乎全场 0 分。

### 4.3 评分必须用扣分制

普通 accuracy 是加分制，无法惩罚"召回了过期事实"。用 **FAMA**（Forgetting-Aware Memory Accuracy）：

```
每题拆两组判据：
  must_include → 当前状态（答对得分）
  must_exclude → 失效状态（命中扣分）

FAMA = w_include × 命中当前 − w_exclude × 命中过期
```

**StateMemBench 更狠**：closed-pool 评分，返回过期事实**不得部分分，直接判 0**。

工程细节：
- **3 个 LLM judge 多数投票**（Memora 报告与人类一致性 88.3%，κ 0.86–0.90）
- **所有对比系统统一 backend**（Memora 全用 GPT-4o-mini），比的才是记忆机制不是模型

### 4.4 四组消融

| # | 验证 | 对照 | 主指标 |
|---|---|---|---|
| **E1** | 门控分离是否有效 | 单一 importance vs 独立 i/f | FAMA、stale recall rate |
| **E2** | 衰减曲线形状 | 指数 vs 幂律 vs 线性 | 第 90/180 天关键记忆存活率 |
| **E3** | 自动更新 vs 固定 | 固定阈值 vs EMA | 参数收敛曲线、误删率 |
| **E4** | 遗忘的净收益 | 无遗忘 vs 有遗忘 | **Pareto：token/query × FAMA** |

**E4 最重要。** 单看"省 30% token"没意义（全删了能省 100%）。必须画 Pareto 前沿，只有曲线整体左上移才算真赢。参考 WMT：+9.97 点准确率 **且** −32.8% token。

> **前置条件**：E1 必须在 Memora 或 StateMemBench 上做。在 LoCoMo 上单分数和分离门的差距会被噪声淹没。

### 4.5 六个方法论陷阱

1. **模型版本漂移** → 固定版本 + `temperature=0` + 多次取中位数，judge 模型也要固定
2. **judge 偏差** → 生成用 A、评测用 B，至少 3 judge
3. **样本量** → 记忆实验方差极大，50 个 case 不可信；必须报 bootstrap CI
4. **平均值掩盖长尾** → 遗忘的失败是长尾的（偶尔删错一条），必须单独报 **false forget rate**
5. **baseline 预算公平** → 和 full-context 比要给**同等 token 预算**，不是比钱
6. **单变量** → 改门控就只改门控，别同时换 embedding 模型

## 五、成本预算

### 5.1 单题成本模型

**假设**（需按实际替换）：输入 ≈ 7K token（检索记忆 6K + 问题 + 标准），输出 ≈ 500 token，judge 3 次/题（每次 7.5K in / 200 out）。单题合计 **输入 ≈ 29.5K，输出 ≈ 1.1K**。

| 模型档位 | 单题成本 | 1000 题 |
|---|---|---|
| 经济档（mini / flash 类） | $0.005 | $5 |
| 中档 | $0.034 | $34 |
| 旗舰档 | $0.105 | $105 |
| **混合**（生成经济 + judge 中档） | **$0.026** | **$26** |

### 5.2 总账

| 轮次 | 配置 × 重复 | 题次 |
|---|---|---|
| StateMemBench（≈700 题） | 4 × 3 | 8,400 |
| Memora weekly 子集（≈400 题） | 4 × 3 | 4,800 |
| Memora quarterly（≈1000 题） | 2 × 3 | 6,000 |
| 开发调试（等效） | — | ~3,000 |
| **合计** | | **≈ 22,200 题次** |

| 档位 | 总成本 |
|---|---|
| 纯经济 | **$113（¥800）** |
| **混合（推荐）** | **$584（¥4100）** |
| 纯旗舰 | $2,330（¥16000） |

### 5.3 省钱四招

1. **judge 用中档**：决定分数可信度，但不需要推理能力，省 4 倍
2. **重复次数比模型档位更贵**：5 次 = 5 倍成本，先 3 次
3. **缓存**：第二轮、第三轮能降到 1/3；embedding 成本可忽略（1 万条 ≈ $0.02）
4. **baseline 只跑一次**：no-memory 和 full-context 是固定对照

### 5.4 设备

**不需要 GPU。** 纯 API + CPU 即可。真正瓶颈是 API 费用和墙上时间。

| 档位 | 配置 |
|---|---|
| 最低（起步） | 4 核 / 16 GB / 100 GB SSD |
| 推荐（全套） | 8 核 / 32 GB / 1 TB SSD |
| 训练（可选） | + 24 GB VRAM，或租卡 ¥50–200 |

**注意**：跑 Zep/Graphiti 做 baseline 需 Neo4j/FalkorDB，Docker 常驻 4–8 GB。

## 九、一句话记住

> **「让 AI 自动调参」可行，但要拆开：写入交给模型（信息现成），遗忘交给使用反馈（延迟信号），衰减率交给记忆类型（零成本）。三者混在一起让模型统一打分，是最常见的失败方式。**
