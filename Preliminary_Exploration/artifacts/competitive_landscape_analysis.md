# Gated-Mem 竞品调研与技术“撞车”深度排查报告

> **调研日期**：2026-11-10  
> **核心结论**：**全球开源界与学术界目前暂无 1:1 完全撞车的方案。**  
> 我们的技术路线处在 **“重型云端图谱（过于昂贵复杂）”** 与 **“现有本地插件（过于简陋无状态）”** 之间的**极具差异化优势的黄金生态位**。

## 1. 竞品全景图与技术特征对比矩阵

当前 AI Agent 长期记忆领域的活跃开源项目与学术方案，主要可分为三大家族：
1. **重型云端/时序图谱派**（Zep / Graphiti, Cognee, HippoRAG）
2. **通用框架与双层记忆派**（Mem0, Letta/MemGPT, LangMem）
3. **Claude Code / Cursor 本地记忆插件派**（`claude-mem`, `@modelcontextprotocol/server-memory`, `Hindsight`）

### 全景横向对比表

| 核心维度 | Zep / Graphiti | Mem0 (原 Embedchain) | Letta (MemGPT) | claude-mem (主流插件) | **Gated-Mem (本方案)** |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **底层定位** | 企业级时序知识图谱 SaaS / 独立服务 | 通用多模态记忆框架 | OS 架构分层记忆系统 | Claude Code 会话历史转储插件 | **面向编码 Agent 的本地可解释状态引擎** |
| **部署与运行开销** | 需独立图数据库/复杂后台服务 | 云端 API 或本地混合，依赖 LLM 提取 | 依赖后台 LLM 频繁自编辑/整理 | SQLite + 本地向量，纯本地 | **单文件 SQLite WAL，纯 CPU < 1ms 数学门控** |
| **新旧事实覆盖机制** | 双时序标记 (`valid_at`/`invalid_at`) | 追加式存储，**在读取时交由 LLM 提示词裁决** | 靠 LLM 自发调用编辑工具替换 Core Memory | **无覆盖机制**，纯向量追加，新旧并存 | **两阶段槽位裁决 (`Subject/Predicate/Scope`)** |
| **废弃关联连坐** | ❌ 无（需 LLM 重新全量遍历清理） | ❌ 无（旧配置与新配置一同被召回） | ❌ 无 | ❌ 无 | **✅ 祖先覆盖连坐坍缩 ($\psi(p)=0.15$)** |
| **深层规则直通** | ❌ 依赖多跳图遍历 (Graph Walk) | ❌ 依赖向量打分截断 | ❌ 依赖分页换入换出 | ❌ 易在预算内被截断 | **✅ 结构残差直连 (`RESIDUAL_SHORTCUT` 0跳)** |
| **变更动因留存** | 仅保留时间戳 | ❌ 无 | ❌ 无 | ❌ 无 | **✅ 状态残差 (`residual_diff` 记录为什么变)** |
| **误杀撤销支持** | 依赖数据库事物回滚 | ❌ 无法无损回滚 | ❌ 无法精准回滚 | ❌ 无 | **✅ 原生不可变事件溯源 ($O(1)$ 一键 `undo`)** |

## 2. 各流派代表项目的逐一解构与差异分析

### 2.1 对比 Zep / Graphiti（时序知识图谱派）
* **竞品做法**：Graphiti 是目前开源界在“时间演进”上做得最深的图引擎。它为每条边打上双时序标签（`valid_at` / `invalid_at`），当检测到反转时，将旧边标记为过期。
* **为什么没撞车？**
  1. **架构沉重**：Graphiti 偏向重型后端服务（需要 Neo4j / 专门图存储引擎），无法作为轻量级单文件插件无感内嵌进个人开发者的日常 IDE。
  2. **缺少“覆盖连坐”**：Graphiti 解决了单条事实的过期（如“A 从 公司X 离职到 公司Y”），但解决不了**层级衍生配置的连坐失效**。当主库从 MySQL 改为 PG 时，旧的连接池、字符集、驱动参数在图谱中无法由纯数学连坐瞬间沉睡，依然会产生上下文污染。
  3. **缺乏结构残差直连**：图遍历随着跳数加深，Token 开销成倍激增，不适合限制严格的 Coding 提示词窗口（500~800 tokens）。

### 2.2 对比 Mem0 与 Letta/MemGPT（通用框架派）
* **竞品做法**：
  * **Mem0**：近期摒弃了硬性 CRUD，改用“只增不减（Add-only）”策略，当新旧事实打架时，Mem0 **放弃在存储层裁决，把新旧两条事实一起喂给 LLM，让 LLM 在生成阶段自己猜哪条是对的**。
  * **Letta**：模拟 OS 内存换页，要求 LLM 在推理过程中自发调用 `core_memory_replace` 等工具维护自身工作区。
* **为什么没撞车？**
  1. **防污染哲学截然不同**：Mem0 让 LLM 读时裁决的代价极其高昂——不仅浪费 Token，而且模型经常在回答中将旧 MySQL 驱动和新 PG 语法杂糅在一起。Gated-Mem 坚持在**输出门（Output Gate）物理拦截**，只向 Agent 暴露干净事实。
  2. **零 LLM 推理开销**：Letta 和 LangMem 需要消耗大量后台 API 费用做“记忆整合与反思”（Memory Consolidation），而 Gated-Mem 的门控生命力计算是 **纯数学闭式解（$< 1$ms，零 API 费用）**。

### 2.3 对比现有本地插件：`claude-mem` 与 Anthropic `server-memory`
* **竞品做法**：
  * `claude-mem`：目前 Claude Code 社区较为流行的插件，通过 Session Hooks 捕获工具调用，大模型总结后存入 SQLite + 向量数据库。
  * `@modelcontextprotocol/server-memory`：Anthropic 官方参考实现，在本地维护一个包含实体（Entity）、关系（Relation）和观察（Observation）的 JSONL 文件。
* **为什么没撞车？**
  1. **完全缺乏状态机与防污染设计**：这批插件本质上是**“无脑追加型日志本”**。你在项目第 1 天写“使用 MySQL”，第 10 天写“改用 PG”，它们会将两条都召回出来，完全无法分辨哪条才是当前真理。
  2. **不可撤销**：大模型误总结了一条错误约束后，开发者无法精准追溯或一键撤回，只能手动打开数据库或 JSON 文件抹除。
  3. **Gated-Mem 降维打击**：Gated-Mem 的目标受众正是受够了 `claude-mem` 过期事实污染的硬核开发者。

## 3. Gated-Mem 的四大独家护城河（Defensibility）

经过全网交叉对比，本方案在学术和开源界具有极强辨识度的独创点在于：

1. **结构化槽位裁决（Slot-Aligned Superseding）**
   * 不盲目迷信余弦相似度（放弃 $>0.9$ 粗暴覆盖），而是比对 `(Subject, Predicate, Scope)`。只有槽位精准对齐且有反转证据才覆盖，拿不准就生成 `CONTRADICTS` 挂起，**误杀率接近 0%**。
2. **数学级拓扑连坐坍缩（Cascading Demotion $\psi=0.15$）**
   * 这是解决“大模型代码生成混淆过时驱动”的杀手锏。主干废除，全链条子孙自动在输出门静默，无需逐条清理。
3. **双重残差流（Dual Residuals）**
   * **结构残差**：深层高频死命令通过金色虚线直连根节点（0 跳直达），既保留模块归属拓扑，又规避了哈夫曼树破坏性重构。
   * **状态残差**：在边属性上记录变更动因 `residual_diff`，实现“忘掉过期代码，但记住演进教训”。
4. **确定性事件溯源与无损时光机（Event-Sourced Undo）**
   * 全生命周期基于 `memory_events`，变更原子化可逆，为自动演进机制提供了终极的安全兜底网。

## 4. 结论与下一步战略建议

* **学术与开源生态位**：目前没有任何开源库在“面向开发者本地编码 Agent”的场景下，完整实现了本方案所定义的门控、连坐、双重残差与事件溯源机制。
* **发布与传播建议**：
  * **精准锚定竞品痛点**：在宣传与文档中，直接对比 `Pure Vector / claude-mem`，以 **“消除过期事实污染（Zero Stale Leak）”** 和 **“一键 Undo 无损时光机”** 作为核心爆点。
  * **基准测试说服力**：利用 Day 6 的 `Golden-Coding-Evolution-50` 测试集，直接给出击败传统向量检索的量化对比数据（如过期泄漏率从 40% 降至 2%）。
