## 一、为什么外部基准是 v1.1 的事，不是 v1.0.0 的事

v1.0.0 交付的是一个可运行的工程内核：两阶段槽位覆盖、`residual_diff` 演进追溯、
有界因果回滚、力导向图谱、零第三方依赖。这些能力由 **181 项单测 + Gate 3 16/16**
覆盖，是"机制正确"的证明。

但它们不是"在公开学术基准上打赢"的证明。把公开发布推迟数周去跑闲聊/问答类基准，
会让一个已经可用的工具在仓库里空转。正确做法是：**先发布可运行的版本，再在独立分支上
诚实地做外部评测，并公开全部结果（包括不理想的）**。

## 三、E1：MemoryAgentBench（CR 子集）

预算：**¥15 ~ ¥30**

### 3.1 必须规避的陷阱：抽槽损失

MemoryAgentBench 的原始数据是**非结构化文本**。如果评测时用一个自由的抽取器把文本
抽成记忆条目，那么抽取器的质量会直接决定后续成绩——一旦抽取有损，A3 槽位机制会被
**冤杀**：它并不是能力不行，而是根本没拿到正确的槽位输入。

### 3.2 解法：Schema-Guided 槽位抽取

`adapters/mab_adapter.py` 的 ingest 阶段必须**提供已有槽位列表**作为约束，
而不是让模型自由发挥：

```
ingest(text, known_slots) -> [
    {subject: <必须来自 known_slots 或显式标记为 NEW>,
     predicate: <同上>,
     value: ...,
     content: ...}
]
```

要点：
1. **槽位闭合**：subject/predicate 优先从 `known_slots` 里选，不允许自由造词。
2. **NEW 标记**：确实无法归入已有槽位时才标 NEW，且需记录，便于审计新增率。
3. **可复现**：抽取结果落盘为中间产物，评测臂 A1..A6 共用同一份抽取结果，
   确保差异只来自检索/门控机制，而不来自抽取随机性。
4. **公平性检查**：抽完后抽样人工核对 ≥10%，抽取准确率低于阈值时，
   必须先修抽取器，而不是继续跑评测。

## 四、E2：Memora（150 题）

预算：**¥20 ~ ¥40**

### 4.1 目标指标

重点验证 `forgetting_absence`：当一条记忆**已经过期/被覆盖**时，系统是否能做到
"不再把它当作当前事实"，同时**不误删**仍然有效的相邻记忆。

这正是本项目"连坐机制物理封印"的对外体现——老祖先废弃时**只告警、不扣分**，
因此不该出现"规则类记忆被上游变更连坐杀死"的现象。

### 4.2 题量规划

| 分组 | 题数 | 说明 |
| :--- | ---: | :--- |
| 遗忘无感（`forgetting_absence`） | 75 | 核心指标 |
| 状态残差追溯（`evolution_why`） | 45 | 验证 `residual_diff` |
| 抗连坐（`anti_trap`） | 30 | 验证不误杀 |
| **合计** | **150** | |

### 4.3 执行分工

* 回答生成：`DeepSeek-V4.1F`
* 异构裁判：`GLM-5.3-Flash`（异构模型评分，避免自评偏差）
* 裁判协议与 prompt 需固化落盘，保证可复现

## 五、预算控制

| 项目 | 上限 | 控制手段 |
| :--- | ---: | :--- |
| E1 MemoryAgentBench | ¥15 ~ ¥30 | 限次调用；抽取结果落盘复用；谷时执行 |
| E2 Memora | ¥20 ~ ¥40 | 单次批量；裁判只跑一遍 |
| **合计硬上限** | **¥50** | 超出即停止，不追加 |

配套纪律：
1. 每次实验前先跑 dry-run，用小样本验证 pipeline，避免整批浪费。
2. 所有 LLM 调用记录 token 用量，实时累计到预算台账。
3. 达到 ¥40 时必须预警，¥50 必须停止。

---

## 六、必须遵守的诚实性约定

1. **不接受"跑不过就不报"**。外部基准结果无论好坏，全部如实公开。
2. **区分机制优势场景与边界限制**：本项目面向"超长开发周期的架构状态演进"，
   在开放域闲聊/回忆类基准上表现一般是可以预期的，这必须写清楚，
   而不是靠调 prompt 把分数刷上去。
3. **不修改基准数据集**，不筛选题目。
4. **给出置信区间或题量**，20 题级别的结论不得表述为"显著优于"。
