### 一、 大模型终审拍板裁决书（Adjudication Verdict）

针对案卷第 5 节的六大待决争议，正式裁决如下：

#### 1. 决策项 1（项目终极定位）：采纳【Option 1-A + Option 1-C 融合定位】



* **最终定位**：**“Git for Agent Memory —— 面向超长开发周期的本地可审计、可回滚架构状态引擎”**。


* **裁决理由**：StateMem Table 6 已确凿证明，在短历史（<15k tokens）下，纯 Prompt Wrapper（71.7~75.0 分）完胜重型持久化存储系统（23.3~36.3 分）。因此，Gated-Mem **严禁在短对话场景与 Prompt 方案争胜**，必须把壁垒焊死在 Prompt Wrapper 物理上做不到的三个痛点上：


1. **跨会话上下文溢出时的确定性状态投影**（项目跨数周、历史超几十万 Token 装不下时）；


2. **架构演进原因追溯（`residual_diff`）**（自动沉淀轻量级 ADR 架构决策记录，回答“当初为什么把 A 换成 B”）；


3. **100% 因果可解释回执（Explain Receipt）与 $O(1)$ 级联撤销（`undo`）**。





#### 2. 决策项 2（核心机制去留）：大刀阔斧砍除负收益复杂度



* **覆盖连坐（$\psi=0.15$）** $\to$ **拍板 [A]：物理砍掉自动连坐降权，改为只读告警标签 `stale_parent_warning**`。


* *依据*：StateMem 消融实验已证实依赖传播在 Anti-trap 上倒退 $-12.5\text{pp}$，去掉后 DeepSeek 总体准确率反而更高（0.373 vs 0.363），且多父 DAG 下 $0.15^k$ 会指数级误杀通用规范。改为：当父节点被 `superseded` 时，子节点不扣减生命力，但在检索注入时自动附带一行提示 `[Warning: 上游依赖节点 X 已废弃，请核实本规则是否仍适用]`。零误杀，且完美体现图谱拓扑价值！




* **结构残差（`RESIDUAL_SHORTCUT`）** $\to$ **拍板 [A]：彻底砍掉**。


* *依据*：补齐检索排序方程后，高频被引用的节点半衰期 $H_v$ 增长、生命力 $F_t(v)$ 接近 1.0，在检索时自然排在最前，无需在图数据库里乱连虚线破坏树状拓扑。




* **状态残差（`residual_diff`）** $\to$ **拍板 [A]：提拔为一等公民核心卖点**。


* *依据*：全网竞品（Mem0/claude-mem）均只管覆盖或共存，没人显式结构化记录“状态变更增量原因”。每次状态覆盖必须写入 `residual_diff`（如 `"因 JSONB 聚合性能不足，由 MySQL 迁移至 PostgreSQL"`）。




* **正向激活扩散（$\gamma$）** $\to$ **拍板 [A]：严格限制为检索期 1-Hop 临时增益（$\gamma=0.2$），不改写数据库持久态，加环路检测**。


* **力导向图 Web UI** $\to$ **拍板 [A/B]：首版砍掉交互式 Web Server，改为 CLI 树状图（`gated-mem graph` 仿 `git log --graph`）+ 静态单文件 HTML 导出器**。既省去 CORS/端口安全隐患，又能生成炫酷的静态图挂在 GitHub README 上吸星。



#### 3. 决策项 3（检索排序方程与数学修正）：固化闭式解



* **检索排序方程（采纳方案 A 乘幂门控）**：



$$\text{Score}(v \mid q) = \text{rel}(q, v) \cdot \left[ F_t(v) \right]^\lambda, \qquad \lambda \in [0, 1] \text{（默认 }\lambda = 0.3\text{）}$$



其中节点固有生命力 $F_t(v)$ 精简为无连坐安全形式：



$$F_t(v) = \begin{cases} 1.0, & \text{if } v.\text{pinned} = 1 \\ \min\left(1.0,\; R(v, \Delta) + \gamma \cdot \max_{u \in \mathcal{N}_{\text{parent}}(v)} \mathbb{I}(u \text{ cited}) R(u, \Delta)\right), & \text{otherwise} \end{cases}$$


* **`input_weight` ($i_v \in [0.1, 1.0]$) 接入公式（采纳选项 A）**：
将输入门权重映射为初始时间尺度乘子：$t_0(v) = t_{0,\text{type}} \cdot (0.5 + i_v)$，从而直接决定初始半衰期 $H_v = t_0(v)(2^{1/\beta_{\text{type}}} - 1)$。


* **单元测试修正**：
废除错误的 `R(2H) == 0.25` 断言，修正为参数化精确断言：`assert math.isclose(R(2*H), (2 * 2**(1/beta) - 1)**(-beta), rel_tol=1e-6)` 且 `assert R(2*H) > 0.25`。



#### 4. 决策项 4（Schema、因果撤销与状态机）：补齐工程闭环



* **因果撤销 Schema**：`memory_events` 表强制增加 `causation_id TEXT`（上游触发事件 ID）与 `correlation_id TEXT`（同批次事务 ID）。执行 `gated-mem undo <event_id>` 时，通过 `WHERE correlation_id = ? OR causation_id = ?` 一次性精确定位所有关联变更并追加逆向补偿事件。


* **拓扑边方向标准化**：`BELONGS_TO` 统一固化为 **`source_id = child` $\to$ `target_id = parent`（子指父）**，并在 `target_id` 上建立索引。


* **状态迁移铁律**：`superseded` 与 `killed` 状态严禁被普通写入覆盖复活，仅允许通过 `undo` 或显式 `restore` 命令恢复。


* **防注入安全边界**：增加 `trust_tier`（`user_verified` > `tool_derived` > `model_inferred`），且注入 Prompt 时强制使用 `<gated_memory_context readonly="true">` 标签包裹隔离。



#### 5. 决策项 5 & 6（零经费验证与开发周期）：10 天敏捷交付 + 三模型免费互测



* 放弃动辄耗资数千元的云端旗舰评测，利用你手头的 **`DeepSeek-V4.1F`、`Gemini-3.8-Flash`、`GLM-5.3-Flash**` 组建“生成-抽取-双盲裁判”流水线，在 **10 天内**完成从「第一刀基准验证」到「开源仓库发布」的全流程。
