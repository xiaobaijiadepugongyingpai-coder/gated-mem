## 2. 黑盒找茬：数据集偏袒与构造迎合量化证据

作为异模型审计者，本节重点揭示这套数据是如何在结构上「保送」C 分支并「封杀」A/B 分支的。以下均为代码实测统计数据：

### 2.1 `must_exclude` 旧词分布：100% 集中于必被覆盖节点

- 在全量 40 组用例中，32 组非控制组均设置了 `must_exclude`（包含 MySQL, Swarm, Memcached 等旧词）。
- **实测排他性统计**：
  - `must_exclude` 关键词落在被覆盖旧节点上的次数：**32 / 32（100.0%）**。
  - `must_exclude` 关键词落在任何未被覆盖的存活/活跃节点上的次数：**0 / 32（0.0%）**。
- **机制后果**：
  - 只要机制实现了「槽位覆盖标杀」（B 分支与 C 分支），旧技术词就会 100% 从活跃候选池中蒸发，`hit_exclude` 必然为 0；
  - 只要机制不做覆盖（A 分支），新旧节点并存，旧词必然进入正文，`hit_exclude` 必然中招。
  - **结论**：A 分支在 non_control 上的 0/32 并非模型检索能力弱，而是被数据集结构性设计彻底锁死。A 的 20.00% 准确率完全等价于控制组占比（8/40）。

### 2.2 `anti_trap` 靶子分布：100% 精准踩在连坐杀伤半径正中心

- 在 32 个非控制组中，`anti_trap` 探针的 `expect_survive` 靶子（M2 规范节点）拓扑位置统计：
  - 是被覆盖旧节点（M1）的**直接子节点（1-Hop）**：**32 / 32（100.0%）**！
  - 是被覆盖旧节点的深层子孙（≥ 2-Hop）：**0 / 32（0.0%）**。
  - 是独立根节点或兄弟节点：**0 / 32（0.0%）**（仅控制组 8 组独立于覆盖链外）。
- **机制后果**：
  - B 分支的连坐机制，其最小作用域就是直接子节点。数据集将靶子 100% 摆放在连坐的直系爆心，导致 B 分支在非控制组上的靶子死亡率达到极端的 100%（32/32 全灭）。
  - B 的 anti_trap 准确率（20.00%）同样完全由控制组比例（8/40）机械决定。若将靶子放在旁系节点，B 的连坐损失将大幅收窄。

### 2.3 传递闭包在全数据集上覆盖为 0（AMB-3 确认）

- 契约 §2 用加粗黑体强调 B 分支沿 parent 边做**传递闭包（全部子孙）**。
- **实测全图拓扑**：
  - 数据集 40 组用例中，被覆盖节点下挂的子节点共 59 个，但**孙辈节点数严格为 0**！
  - 仿真实验证明：将 B 分支算法削弱为「仅标直接子节点（1-Hop）」，与完整的 BFS/DFS 传递闭包算法相比，在全量 120 条探针上的输出与判定**完全无差异（0/120 差异）**。
  - **结论**：契约重点声明的多跳传递闭包能力，在当前测试集上处于**零覆盖盲区**。

### 2.4 TOPK 截断机制严重退化：90%~100% 退化为「全集注入」

这是此前审计报告未曾量化的重要盲点：
- 契约规定检索截断参数 `TOPK = 5`。
- **活跃候选集大小统计**：
  - **A 分支**：无覆盖，候选数恒为 6~7 个（6 个 108 次，7 个 12 次），发生 TOPK 截断。
  - **B 分支**：由于覆盖及连坐杀伤，活跃候选节点数萎缩为 3（69 次）、4（27 次）、5（24 次）。**活跃候选数 ≤ 5 的比例高达 120/120（100.00%）**！
  - **C 分支**：活跃候选节点数萎缩为 5（108 次）、6（12 次）。**活跃候选数 ≤ 5 的比例高达 108/120（90.00%）**！
- **机制后果**：
  - 在 B 分支中，100% 的探针注入了所有的活跃节点；在 C 分支中，90% 的探针注入了所有的活跃节点。
  - 排序公式 `Score = rel * (F ** LAMBDA)` 在 B/C 分支上基本**没有发挥筛选与淘汰作用**，只是走了一个排序形式。
  - 阶段一测试的实质是**图节点 status 的标杀准确性**，而非向量与时间衰减在多候选环境下的**排序淘汰能力**。

### 2.5 控制组声明核查（docs/phase1_handoff.md 验算）

- **核查项 1**：声称「A 在控制组 8/8 满分」。
  - **验算**：A 在控制组的 current_state 为 8/8（100%），anti_trap 为 8/8（100%）；但 evolution_why 为 0/8（0.0%）。
  - **评价**：声明在限定为 current_state / anti_trap 维度时属实；但必须明确澄清 A 分支由于契约设计不记录 diff，在 evolution_why 维度不可能拿满分。
- **核查项 2**：声称「B 在控制组 8/8 满分」。
  - **验算**：B 在控制组 current_state = 8/8, anti_trap = 8/8, evolution_why = 8/8，3 探针全满分（24/24 命中）。声明完全属实。

## 3. 对「这份数据能否支撑阶段一结论」的审慎判断

### **判断结论：【有条件能（Conditionally Support）】**

本审计人认为，这份数据与消融实验**能够**完成阶段一的使命，但**必须附加严格的前提条件与边界限定**：

#### 能够支撑的部分（机制有效性的首刀证明）：
1. **槽位覆盖的方向正确性**：证明了基于 `(subject, predicate, scope)` 精确三元组的状态覆盖机制是消除当前态污染的有效手段（A vs C 的 current_state 对比）。
2. **强连坐的副作用被实证捕获**：不仅捕获了连坐误杀旧规范（anti_trap -80pp），还意外捕获了连坐误杀新事实上下文（B 分支 S07/S19/S35 在 current_state 上掉分至 92.5%）。这直接论证了 C 分支 `stale_parent_warning`（只告警不标杀）的设计价值。
3. **回执通道双通道隔离成立**：证明了 `[Replaced: ...]` 进入 `returned_diff` 而不污染 `injected_text` 的工程方案切实可行，有效封堵了回执旧词自伤的死穴。

#### 不能支撑且绝对禁止外推的部分（不可作为通用 SOTA 依据）：
1. **禁止外推为复杂知识图谱通用能力**：40 组用例结构高度同构（单次覆盖、无孙辈、旧词排他分布）。
2. **禁止外推为检索排序（Ranking）的优越性**：因候选池（3~6 个）与 TOPK=5 高度贴合，90% 以上情况未发生真实淘汰。
3. **禁止声称传递闭包已被验证**：B 分支传递闭包在深度 1 处截断，数据未包含多跳链。

## 5. 门禁 1 最终签署结论

基于本模型的独立复算、360 条 run 的零分歧核对、以及对数据构造边界的全面审计：

### **签署结论：【同意放行门禁 1】（附带阶段二硬性整改条件）**

```yaml
gate1_crosscheck_signoff:
  auditor: "gemini_audit (antigravity/gemini-3.8-flash)"
  independent_recomputation:
    A_current_state: 0.200000
    A_anti_trap: 1.000000
    A_evolution_why: 0.000000
    B_current_state: 0.925000
    B_anti_trap: 0.200000
    B_evolution_why: 1.000000
    C_current_state: 1.000000
    C_anti_trap: 1.000000
    C_evolution_why: 1.000000
  gates:
    G1_current_state_lead_pp: { delta_pp: 80.00, threshold_pp: 20.0, pass: true }
    G2_anti_trap_c_gt_b: { b: 0.20, c: 1.00, pass: true }
    G3_evolution_why: { c: 1.00, threshold: 0.85, pass: true }
    overall_pass: true
  verdict: "PASS"
```

### 签署理由：
1. **数学与逻辑的一致性**：在当前冻结契约 CONTRACT v1.0.0 与数据集规范下，无论是状态机流转、时间衰减与生命力数学积分、分词集合比对、还是双通道回执提取，实现均与契约完全一致，不存在实现偷生或违规取巧。
2. **阶段定位匹配**：阶段一定位为「首刀验证（Spike Cut）」，其核心目标是验证「槽位覆盖、双通道隔离、不连坐」的核心假设是否成立。数据虽有构造红利，但确实清晰展示了机制的有效性与连坐的负收益。

### 阶段二必须继承的 3 项硬性整改清单（P0 级约束）：
1. **【P0-数据】补齐多跳深度演进集**：新增三代及以上演进用例（`覆盖祖先 -> 父节点 -> 子孙节点`），使传递闭包真正经历测试，打破当前 1-Hop 的虚假繁荣。
2. **【P0-数据】扩大候选池，恢复 TOPK 排序筛选功能**：用例事件规模扩大至 15~30 节点，确保活跃候选集远大于 TOPK，严格考核 `rel * F^LAMBDA` 的真实排序能力。
3. **【P0-规范】`stale_parent_warning` 显式落盘**：契约 1.0.1 及阶段二 SQLite Schema 必须显式持久化并暴露 stale 警告，禁止停留在无痕内部状态。
